[hx 0.9.3](@/blog/hx-and-the-2026-haskell-toolchain.md) brought hx up to date with the 2026 toolchain. hx 0.10.0 is about everything that happens after the toolchain is in place: installing the tools you work with, growing a project into several packages, building the same thing twice, and sharing what you build.

## Install Haskell tools in one command

`hx install` is the Haskell counterpart of `cargo install`. It builds a package's executables with your hx-managed GHC and Cabal and puts them in `~/.hx/bin`:

```bash
hx install hlint                  # latest version from Hackage
hx install fourmolu@0.18.0        # a specific version
hx install --git https://github.com/ndmitchell/hlint --rev v3.8
hx install --path .               # the executables of this project
```

hx records what it installed in `~/.hx/installed.toml`, so it knows which files belong to which package:

```bash
hx install --list
hx uninstall hlint
```

Installing a version you already have is instant, `--force` rebuilds, and hx never overwrites an executable that another package owns.

## Workspaces

Projects grow into several packages: a library, a server that uses it, a command-line tool next to them. hx 0.10.0 treats that as a first-class shape.

```bash
hx workspace init               # adopt the package directories below
hx workspace add tools/migrate  # add a member
hx workspace list               # members, versions, and what depends on what
```

`cabal.project` stays the single list of members, so cabal and hx always agree. From the workspace root, `hx build`, `hx test` and `hx check` act on every member; from inside a member directory they act on that member, while sharing the root's lockfile, build directory and toolchain. `-p` selects members explicitly and can be repeated.

The most useful flag in daily work is `--changed`:

```bash
hx test --changed          # members touched since HEAD, plus what depends on them
hx test --changed main     # everything affected on this branch
```

hx maps changed files to the members that contain them, adds every member that depends on those inside the workspace, and runs only their tests.

## Lockfiles you can verify and build offline

`hx.lock` now pins every dependency by the SHA-256 of its source tarball and by the exact Hackage `.cabal` revision, together with the index state, compiler and platform the plan was resolved for. The hashes come straight from the Hackage index, so locking downloads nothing.

```bash
hx lock            # resolve and pin
hx fetch           # download every locked source and verify its hash
hx sync --offline  # build from those sources, no network needed
```

`hx sync` builds with exactly what the lockfile records: versions, flags and index state. A tarball that does not match its hash is refused. For CI there is one command that checks the lockfile against `hx.toml`, the `.cabal` files, the Hackage index and the cached sources:

```bash
hx lock --check
```

Existing lockfiles keep working and move to the new format the next time you run `hx lock`.

## The arcanist.sh registry

hx 0.10.0 comes with support for package registries, and with one built in: [registry.arcanist.sh](https://arcanist.sh/registry/), a Haskell package repository for the arcanist.sh ecosystem. It serves the same format as Hackage and signs everything with hackage-security, so plain cabal can use it next to Hackage. hx writes the configuration for you:

```bash
hx registry add                       # adds the signed repository stanza to cabal.project
hx search --registry arcanist hello
hx registry info arcanist-hello
```

After `hx registry add`, `cabal update` verifies the registry's signed metadata against its root keys, which are published at [arcanist.sh/registry](https://arcanist.sh/registry/), and packages from both repositories resolve in one plan. Publishing is a single flag on the command you already use:

```bash
hx registry login
hx publish --registry arcanist
```

The registry is in preview, and publishing accounts are issued by invitation while it runs. A verifier builds new versions with BHC and records the result, so `hx registry info` can show which versions are BHC-verified. Hackage remains hx's default.

## Always the current toolchain

hx now reads GHC, Cabal and HLS releases, recommendations, download URLs and checksums from the metadata ghcup publishes. New releases reach hx within a day of ghcup listing them, without an hx update, and every download is verified against the published checksum. On Linux, hx picks the build made for your distribution, including Alpine.

```bash
hx toolchain list              # installed, recommended and latest
hx toolchain list --available  # every current release
```

`hx doctor` mentions when a newer recommended release is available. Versions you pin in `hx.toml` always win, and without a network hx falls back to its built-in tables.

## Testing with BHC

`hx test --backend bhc` builds each test suite from your `.cabal` file with BHC, runs it, and reports the result per suite. `--package` picks a member or a single suite, and `--pattern` is passed to hspec or tasty in the form each expects.

## Where hx keeps things

```bash
hx config path --all
```

lists every location hx reads or writes, from the config file to caches, the Cabal store and toolchains, together with the setting that chose it. `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` now apply to every one of them on every platform, as do `HX_CACHE_DIR`, `HX_STORE_DIR` and `HX_HOME`. Default locations are unchanged.

## And underneath

- The Linux release binaries run on Debian 10, Ubuntu 20.04, RHEL 8 and everything newer, and `install.sh` installs the fully static build on x86_64 Linux, so hx runs on any distribution.
- hx trusts the operating system's certificate store as well as its bundled roots, and honours `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY`, so it works behind corporate TLS proxies.
- A container image and the FlakeHub flake are published with every release.

## Getting it

```bash
curl -fsSL https://arcanist.sh/hx/install.sh | sh   # new install
hx upgrade                                          # existing install
```

With Homebrew, `brew upgrade arcanist-sh/tap/hx`. The full list of changes is in the [changelog](https://github.com/arcanist-sh/hx/blob/main/CHANGELOG.md).
